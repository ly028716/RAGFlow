# 本地知识库 RAG Agent 部署文档

## 部署边界

- **本地持久化**：MySQL（业务数据）、Redis（缓存与限流）和 Chroma（向量索引）。
- **在线模型**：仅 DashScope。LLM 为 `qwen-plus`，Embedding 为 `text-embedding-v3`。
- **受限工具**：查询改写、知识库检索、上下文选择、引用校验。服务不会向外部网站检索或抓取内容。

## Docker Compose

```bash
cd backend
cp .env.docker .env
# 在 .env 中设置 DASHSCOPE_API_KEY 和强 SECRET_KEY
docker compose up -d
docker compose exec backend alembic upgrade head
docker compose ps
```

前端：<http://localhost:5173>；后端 OpenAPI：<http://localhost:8000/docs>。

生产环境使用 `docker compose -f docker-compose.prod.yml up -d`。上线前把 `.env.prod.example` 复制为私有环境文件，替换所有数据库、Redis、JWT 和 DashScope 密钥占位值。

## 必需模型配置

```dotenv
DASHSCOPE_API_KEY=sk-...
LLM_PROVIDER=dashscope
LLM_MODEL=qwen-plus
EMBEDDING_PROVIDER=dashscope
EMBEDDING_MODEL=text-embedding-v3
```

这四项是部署契约：`LLM_PROVIDER` 或 `EMBEDDING_PROVIDER` 不是 `dashscope` 时，配置校验会阻止服务启动。Docker Compose 已将这些变量传递给后端。模型调用会产生费用，应设置 DashScope 额度告警。

## 上线检查

1. `DASHSCOPE_API_KEY`、`SECRET_KEY`、数据库密码和 Redis 密码均来自受控密钥系统。
2. 为 Chroma 挂载持久化卷，并定期备份 MySQL 与向量目录。
3. 执行 `alembic upgrade head`，再检查 `/api/v1/system/health`。
4. 使用低权限用户创建一个测试知识库，上传文档后在 `/agent` 验证答案、来源和引用校验。
5. 在生产环境限制 CORS 域名，监控 DashScope 错误率、首 Token 延迟和检索耗时。

## 常见故障

| 现象 | 排查方式 |
| --- | --- |
| LLM/Embedding 调用失败 | 检查 `DASHSCOPE_API_KEY`、DashScope 配额和容器日志。 |
| 没有检索结果 | 确认文档处理完成、所选知识库有权限、Top-K 与相似度阈值合理。 |
| 引用校验失败 | 查看 Agent 执行轨迹中的最终上下文和 `citation_validation`，不要让模型使用上下文外事实。 |
| Chroma 数据丢失 | 检查 `CHROMA_PERSIST_DIRECTORY` 对应的宿主机挂载和备份策略。 |

## 历史迁移提示

迁移 `009` 至 `011` 为历史版本，必须保留以保证既有数据库可以顺序升级。`012_remove_openclaw_tables` 只清理历史集成表；历史 Web Scraper 表和数据不会被该迁移删除，也不会作为当前运行时功能暴露。
