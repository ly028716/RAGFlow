# 本地知识库 RAG Agent 测试文档

## 测试目标

验证受限 RAG 链路的正确性、权限边界、流式合约和可解释性，而不是验证外部工具集成。

| 范围 | 重点 |
| --- | --- |
| 服务单元测试 | 查询改写、上下文预算与引用校验。 |
| Agent 测试 | 固定四工具、知识库授权范围、步骤轨迹和 Token/耗时。 |
| RAG API 测试 | 非流式响应与 SSE 的 `sources → token* → done` 顺序。 |
| 权限与韧性测试 | 多知识库隔离、无权限拒绝、DashScope 重试与错误收敛。 |
| 向量一致性测试 | 删除知识库前清理对应 Chroma collection。 |
| 前端测试 | Agent 调试时间线、来源卡片、指标和引用校验渲染。 |

## 评测回归

固定问题集位于 [rag-evaluation-dataset.jsonl](./rag-evaluation-dataset.jsonl)，报告模板位于 [RAG评估报告.md](./RAG评估报告.md)。每次调整分块、检索参数、提示词或模型版本后：

1. 导入同一批演示文档并记录真实 `document_id`。
2. 逐题执行 RAG/Agent，保留 `sources`、`done` 事件和执行轨迹。
3. 计算 Recall@K、Hit Rate、Faithfulness、Answer Relevancy、平均检索耗时和首 Token 延迟。
4. 与基线报告比较；指标退化时检查改写、阈值、上下文截断或引用校验。

## 通过标准

- 任何答案都只能引用本次检索的片段 ID；未知引用必须使 `citation_validation.valid=false`。
- 无权访问的知识库不得进入检索范围或来源列表。
- 正常流式响应以一个 `done` 事件结束，失败响应以一个 `error` 事件结束。
- 测试不能依赖真实生产密钥；LLM 与 DashScope 调用应通过受控 stub/mock 覆盖异常分支。
